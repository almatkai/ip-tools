Standalone schema-3 / process / protocol-1 executable. All nine V1 command IDs and the optional misspelled `keywork` argument are preserved. V1 files remain unchanged except the root README discovery link. This package contains no JS runtime or compiled-in host adapter.

SDK: `tezbar-extension-sdk 0.1.1`, immutable HTTPS Git revision `e955911f0bf5b558f9d3eb5183df0adc95c22af2`. Host contracts and renderer fixtures are exact Git objects from `ea100cee3f69711de12485ba061950c5fc65258f`; no host working file was used. See [validation](VALIDATION.md), [icon provenance](qa/icon-provenance.json), and [reference hashes](qa/reference-hashes.json).

Commands: `ip2long`, `long2ip`, `ip2BinHex`, `parseCIDR`, `isValidIP`, `isValidCIDR`, `toIPv6Format`, `toIPv6Expand`, `geoLocation`. Their ordered rows, messages, clipboard text, numeric domains and original spelling (`comperssed`) follow actual TSX and locked `ip-toolkit 1.0.20`, `json-bigint 1.0.0`, and `axios 1.20.0`. In particular, IP-to-bin/hex “Copy All to Clipboard” copies the original scalar decimal, and CIDR Copy All preserves unquoted BigInt values. IPv4 leading zeros, CIDR numeric coercion and IPv6 validation/expansion quirks are intentional. Rust std IP parsing is not the compatibility authority.

## State, delivery and host prerequisite

Native input handling revokes old rows/tokens and cancels outstanding work before validation, including malformed/nonstring/oversized inputs. A session-owned cleanup guard releases the adapter's weak registry on cancelled open, disposal, EOF and shutdown. The SDK independently cancels superseded searches in reader order. Result invalidations are scoped/revisioned. Dropdown controls have reusable value-change IDs; clipboard actions use session-owned random consumable tokens.

Clipboard bytes are frozen from displayed results and token consumption happens before awaiting reverse RPC, outside SDK staged JSON. Success accepts only the actual closed `{ok:true,message?:string}` acknowledgement and issues fresh repeat tokens. Failure, timeout, cancellation or unknown ACK leaves a truthful unknown-outcome notice and an explicit **Retry Exact Copy** using the original bytes. Late ACKs and duplicate/foreign/stale tokens cannot revive a consumed token. This does not provide exactly-once clipboard delivery. There are no invented confirmation stages, clipboard reads, paste, browser, focus or visibility effects: V1 does not use them.

[The unapplied renderer patch](integration/renderer-ownership.patch) is a host prerequisite. For a native list declaring `root.props.__clientInputAction = "control:input"`, every deliberate text or dropdown event dispatches the complete current draft through existing `extensionInvokeAction.formValues = { searchText, value, revision }`. `__clientChoice` supplies the initial choice; `__clientRevision` acknowledges the applied draft. No new top-level bridge request field or SDK fork is used. The reusable dropdown ID stays `control:choice`; it is not a consumable clipboard token. The transport action is separate from visible effect actions.

Client revisions increase independently of native model/effect epochs, including A/B/A and repeated equal choices. The adapter rejects old/equal revisions before changing the draft, while each new valid revision revokes previous rows/tokens and cancels owned work before query/choice validation. A legacy search/control mutation cannot acknowledge an atomic draft and does not reset its revision floor. Revisions are bounded to the JavaScript safe-integer range; reaching the limit requires reopening the session. The renderer retains one current draft and ownership counters rather than an input history; models never advance its client revision.

Rows/effects are hidden immediately when new input begins. Failed, unchanged, no-view and rejected replies release only that request's busy ownership. New inputs remain usable, while old effects stay blocked until an exact-revision, same-session/generation view acknowledges the complete draft. The error panel's **Refresh** button performs read-only recovery; it does not resend input or start another geo request. Stale completions/errors and callbacks from replaced sessions or unmounted components cannot publish or release newer ownership. List text remains client-owned across native models/ACKs; dropdown restoration and original empty-state messages are preserved. Legacy lists without the atomic declaration retain their existing search RPC route.

Actual complete pinned/proposed component functions are executed with controlled React/hooks and dependency boundaries, including a real SDK subprocess with crossed wire order and independently delayed host completions. The proposed bridge/shared definitions are also compiler-checked against immutable Git objects. This is isolated evidence: the patch has **not** been integrated into or accepted by Tezbar, and desktop acceptance remains unrun.

## Bounded adaptations

Geolocation retains the original provider and exact interpolation: `http://ip-api.com/json/{ip}?lang={en|zh-CN}&&fields=61151`, including automatic empty-input lookup. It performs real HTTP using reqwest; it does not switch providers or silently upgrade the provider to HTTPS. The production executable has no fixture endpoint, trust override, insecure switch, environment transport bypass, credential or persistent result cache. Trusted fixture CA use exists only in a separate unshipped helper.

After input-time revocation, geolocation waits 200 ms, approximating the native input throttle. Ordinary conversion/validation dispatch is immediate to make revocation safe. Requests have 3 s connect / 5 s total deadlines and at most 5 redirects (locked axios defaults to no timeout and 21 redirects). Responses are limited to 64 KiB, 128 fields, depth 12 and 512 nodes; they must be JSON objects with finite JS-number values. The original provider's ordinary scalar fields and JS double rounding/JSON formatting are retained. Compressed response negotiation and environment proxies are not enabled. V1 would also display arbitrary non-object responses or nonfinite parsed numbers; this bounded port instead shows its original `status: fail` result. Errors contain no address, URL, response body or host error text. Requests are cancelled by dropping owned futures; process shutdown also bounds waiting for OS DNS to 2 s. No automatic request retry is added.

Input is bounded to 4096 UTF-8 bytes; malformed native payloads show an explicit error. Source-accepted values that throw in the original toolkit (for example fractional CIDR prefixes or malformed zone-suffix expansion) show a safe conversion error instead of crashing the command. Source action order/bytes are retained; native layout uses the host list/action panel and text loading indication. A finite oracle corpus is evidence for its tested cases, not universal JS/Rust parity.

`storeValue` dropdown choices are the only persisted state: `dataDir/dropdowns.json`, at most 4096 bytes and eight declared controls. Writes use a process-wide serialized read/modify/atomic replacement, private Unix directory/file permissions and sync. Invalid, oversized or symlinked state is reported and never overwritten. Choices are stored per command; Raycast's private cache key is not available, so that key mapping is an explicit adaptation. There is no query/result/action persistence. Serialization prevents same-process ABA/lost updates; cross-process coordination relies on the host's one-process-per-extension/profile rule, not a cross-process CAS. The host-supplied private data directory must remain trusted.
